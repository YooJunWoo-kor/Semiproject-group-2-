재무관리 파일 안내
작성 기준: 2026-11-16 업로드한 finance(6).zip
기준 위치: frontend/src/pages/Main/finance/

1. 폴더를 읽는 순서

FinanceHom.js      재무관리 메뉴와 하위 화면 연결
FinanceModul.js    재무관리 홈(대시보드)
pages/            메뉴별 화면과 사용자 동작
components/       재무관리 안에서 재사용하는 UI와 기능

DB를 직접 조회하는 코드는 이 프론트엔드 폴더에 없습니다.
화면에서 API를 요청하면 백엔드 라우터와 쿼리가 DB를 조회합니다.

2. 루트 파일

[FinanceHom.js]
- 재무관리 전체 레이아웃, 메뉴, 하위 라우팅을 담당합니다.
- 파일명은 FinanceHom.js이고 기본 내보내기 컴포넌트명은 FinanceHome입니다.
- 재무관리 홈에는 FinanceModul을 표시합니다.
- funds에서는 법인카드/회사계좌 탭을 표시합니다.
- partners에서는 Partners를 표시합니다.
- items에서는 FinanceWorkspace를 표시합니다.
- 이전 corp-card, bank-account, approval 주소는 새 화면으로 이동시킵니다.
- 파일 내부의 FinanceFunds 함수는 자금관리 탭을 구성하는 화면입니다.
  components/FinanceFunds.js와 이름이 비슷하지만 서로 다른 역할입니다.

[FinanceModul.js]
- 재무관리 홈(대시보드)을 담당합니다.
- 통계 카드, 일정, 조회 결과, 문서 작성 창을 구성합니다.
- 공용 StatisticsCard, ScheduleBoard, ModalBase 등을 사용합니다.
- 영수증/청구서/견적서 작성에는 FinanceDocumentForm을 사용합니다.

3. pages: 메뉴별 화면

[pages/FinanceWorkspace.js]
- 지출·거래 관리 화면의 진입점입니다.
- 기본 화면은 PaymentManagement입니다.
- view=legacy이면 기존 결재·이력 화면인 Approval을 표시합니다.
- MASTER 또는 department_id가 1인 사용자인지 확인합니다.

[pages/PaymentManagement.js]
- 지출·거래 관리의 분류 및 조회 화면입니다.
- 분류 데이터 조회와 저장, 거래 목록 및 결재 화면 연결을 담당합니다.
- Items와 Approval을 내부 화면 또는 모달에서 사용합니다.
- 실제 화면에 사용 중인 파일이므로 이름에 Management가 있다고
  사용하지 않는 구버전 파일로 판단하여 삭제하면 안 됩니다.

[pages/Items.js]
- 매입·매출 거래 및 품목 목록과 상세를 담당합니다.
- 거래·품목 등록/수정/삭제, 입출금 처리, 관련 이력 등을 연결합니다.
- 승인 문서와 월별 급여를 목록 행으로 변환할 때 financeUtils를 사용합니다.
- 상세 행과 이력 표에는 FinanceDetailUI, FinanceFunds 등을 사용합니다.

[pages/Approval.js]
- 결재 문서 목록, 상세, 승인/반려 등 결재 동작을 담당합니다.
- 지급 등록·조회에는 FinanceApproval의 ApprovalPayments를 사용합니다.
- 첨부파일에는 FinanceApproval의 FinanceAttachments를 사용합니다.
- 문서 승인 상태와 지급 완료 상태는 별개의 상태입니다.

[pages/CorpCard.js]
- 법인카드 목록, 등록/수정, 사용 상태 및 한도 관리를 담당합니다.
- 카드 입출금 이력 조회와 표시에는 FinanceFunds를 사용합니다.
- 서버 카드 데이터는 financeUtils의 toFinanceCard로 변환합니다.

[pages/BankAccount.js]
- 회사계좌 목록, 등록/수정, 사용 상태와 잔액 표시를 담당합니다.
- 계좌 입출금 이력 조회와 표시에는 FinanceFunds를 사용합니다.

[pages/Partners.js]
- 거래처 목록, 검색, 등록/수정/삭제, 상세를 담당합니다.
- 거래처 마감일·달력 색상 등 관련 화면 처리를 포함합니다.
- 상세창과 합계 등 공용 UI는 FinanceDetailUI를 사용합니다.

4. components: 재무 전용 UI와 유틸

[components/FinanceApproval.js]
내보내는 항목:
- ApprovalPayments: 승인 문서의 지급 현황·이력 조회, 지급 등록 폼
- FinanceAttachments: 결재 첨부파일 목록·업로드·다운로드
주의:
- 파일명과 내보내는 함수명이 다릅니다.
- ApprovalPayments.js, FinanceAttachments.js로 따로 나눠진 구조가 아닙니다.

[components/FinanceDetailUI.js]
내보내는 항목:
- FinanceDetailRows: 기존 table의 tbody에 넣는 항목명/값 행
- FinanceResourceModal: 재무 전용 상세·이력 모달 틀
- FinanceResourceDetails: 표를 포함한 상세 항목 영역
- FinanceSearchForm: 선택 필터·검색어·조회 버튼
- FinanceStatusBadge: 상태 문구를 표시하는 배지
- FinanceSummaryBox: 합계/잔액 등 금액 요약 박스
주의:
- 상태 판정이나 합계 계산은 주로 사용하는 화면에서 전달합니다.
- 여러 재무 화면이 함께 사용하므로 변경 시 다른 사용 화면도 확인합니다.

[components/FinanceFunds.js]
내보내는 항목:
- FinancePaymentHistory: 입출금 이력 표, 선택적 월 필터와 합계
- useFinanceHistory: 선택 항목의 이력 조회 및 로딩/오류 상태 관리 훅
주의:
- FinanceSummaryBox를 FinanceDetailUI에서 가져옵니다.
- FinanceHom.js 내부의 자금관리 화면 함수와 구분합니다.

[components/FinanceDocumentForm.js]
- 영수증·청구서·견적서 입력 및 미리보기 화면입니다.
- 문서 저장과 인쇄 동작을 연결합니다.
- FinanceModul.js에서 사용하므로 삭제하면 안 됩니다.
- 기본 내보내기(default export)를 사용합니다.

[components/financeDocumentUtils.js]
- 문서 종류 설정, 날짜/통화 표시, 반올림을 담당합니다.
- 품목별 금액과 문서 전체 합계를 계산합니다.
- 문서 인쇄, 입력 검증, 저장/목록/상세/거래처 조회 API를 포함합니다.
- FinanceDocumentForm과 함께 사용하는 문서 전용 유틸입니다.
- localDate는 로컬 날짜를 사용합니다. 아래 koreaDate와 기준이 다릅니다.

[components/financeUtils.js]
- 재무관리에서 사용하는 일반 유틸을 모은 파일입니다.
- 전체 프로젝트의 src/utils가 아니라 재무 전용 파일입니다.
내보내는 함수:
- getFinanceError: 서버 오류 메시지 또는 기본 오류 문구 반환
- koreaDate: 한국 시간 기준 YYYY-MM-DD 날짜 반환
- toFinanceCard: 카드 API 응답을 화면용 데이터로 변환
- normalizeApprovalStatus: 승인/미승인/알 수 없음 상태로 정규화
- toApprovedTradeRows: 결재·기안서 데이터를 거래 목록 행으로 변환
- toPayrollPurchaseRows: 승인된 월별 급여 집계를 매입 목록 행으로 변환
주의:
- 이 함수들이 DB에 거래를 생성하는 것은 아닙니다.
- toApprovedTradeRows는 미승인 상태도 정규화하여 다룹니다.
  함수명만 보고 모든 반환 행이 승인 완료라고 판단하지 않습니다.
- toPayrollPurchaseRows는 approval_status가 'APPROVED'인 항목만 사용합니다.
- normalizeApprovalStatus는 한글 '승인'과 영문 'APPROVED'를 모두 인식하지만,
  급여 함수의 조건은 별도이므로 두 동작을 혼동하지 않습니다.

[components/Finance.css]
- 재무관리 대시보드, 목록, 상세, 버튼 등 화면 스타일을 담당합니다.
- 프로젝트 공통 CSS와 함께 사용됩니다.
- 글자 크기 등은 개별 컴포넌트의 인라인 style에도 있을 수 있습니다.

6. 급여 승인 데이터 확인 방법

프론트 처리:
- toPayrollPurchaseRows는 서버에서 받은 summaries를 화면 데이터로 변환합니다.
- 승인 여부, 월 형식, 금액/인원, 중복 월을 확인합니다.
- DB 조회 자체는 백엔드에서 수행합니다.

별도로 확인한 queries.zip의 백엔드 기준:
- routes/finance/payrollRoutes.js의 GET /payrolls/summary에서 조회합니다.
- queries/finance/payrollQueries.js의 selectPayrolls를 사용합니다.
- payrolls.draft_id와 my_draft.draft_id를 연결합니다.
- my_draft.status = 'APPROVED'인 급여만 월별 합산합니다.
- 결과에는 'APPROVED' AS approval_status를 넣어 반환합니다.
- 이미 거래로 연결된 기안서의 급여는 중복 표시 방지를 위해 제외합니다.

한글 '승인'도 DB에서 허용하려면:
- 급여 목록·상세·지급 등록 쿼리의 조건을 함께 맞춰야 합니다.
- 예: d.status IN ('APPROVED', '승인')
- 이전에 확인한 백엔드 파일의 실제 조건은 'APPROVED' 비교였습니다.
  이후 수정 여부는 이번 프론트 ZIP만으로 확인할 수 없습니다.

8. 함께 사용하는 프로젝트 공용 파일

이 ZIP 밖의 주요 의존 파일:
- src/utils/financeService: 재무 API 요청
- src/utils/authStorage: 로그인 사용자, API 주소, 공통 설정
- src/utils/validation: 이메일·전화번호·사업자번호·길이·날짜 범위 검증
- src/components의 표, 페이지네이션, 모달, 달력, 통계 카드, 필터 등
- src/css의 프로젝트 공통 스타일

공용 파일은 다른 모듈도 사용하므로 영향 범위를 확인한 후 수정합니다.
이 안내는 업로드된 소스를 읽어 작성했으며 전체 실행 빌드 검증 결과는 아닙니다.
