재무관리 프론트엔드 파일 안내
작성 기준: 2026-11-16 / UI 공통화 적용 버전
권장 보관 위치: frontend/src/pages/Main/finance/재무관리_파일안내.txt

이 파일은 팀원이 재무 화면의 구성과 수정 위치를 찾기 위한 안내입니다.
프론트엔드 기준이며 백엔드 라우터·DB 쿼리 파일은 설명 범위에 포함하지 않습니다.


1. 먼저 확인할 파일

FinanceHom.js
  - 재무관리 진입점입니다. 파일명은 FinanceHom.js, 컴포넌트명은 FinanceHome입니다.
  - 왼쪽 메뉴와 재무 하위 페이지의 라우팅을 관리합니다.
  - 같은 파일의 FinanceFunds에서 법인카드/회사계좌 탭과 자금 요약을 구성합니다.
  - 메뉴·주소·자금 관리 탭 연결을 바꾸려면 이 파일을 확인합니다.

FinanceModul.js
  - 재무 메인 화면(대시보드)입니다.
  - 달력, 지급 완료/예정 통계, 일정 상세조회, 영수증·청구서·견적서 작성 연결을 담당합니다.
  - 메인 화면 배치와 요약 표시를 바꾸려면 이 파일을 확인합니다.


2. pages 폴더: 실제 업무 화면

FinanceWorkspace.js
  - 지출·거래 관리의 상위 화면입니다.
  - 거래 현황(PaymentManagement)과 기존 결재·이력(Approval)을 연결합니다.
  - 화면 전환 및 해당 화면의 이용 권한을 확인합니다.

PaymentManagement.js
  - 조회 월에 따른 입출금·미정산 현황과 지출/수입 분류를 표시합니다.
  - 분류 선택·변경, 거래 목록 및 결재 상세 연결을 담당합니다.
  - 통합 화면 안에서 Items를 재사용합니다.

Items.js
  - 매입·매출 품목 등록/수정/삭제, 거래 전표와 입출금 등록을 담당합니다.
  - 결재 문서의 거래 연결, 승인 급여·공제액 조회와 지급 등록도 포함합니다.
  - 품목·급여·공제의 업무별 검증과 처리 흐름은 이 파일에서 확인합니다.

Partners.js
  - 거래처 목록/등록/수정/삭제 및 상세정보를 담당합니다.
  - 거래처별 미정산 금액, 정기 마감일, 달력 색상과 마감 일정을 관리합니다.

BankAccount.js
  - 회사계좌 목록, 등록/수정, 잔액, 입출금 이력과 사용 상태를 관리합니다.
  - FinanceHom의 자금 관리 안에서 회사계좌 탭으로 재사용합니다.

CorpCard.js
  - 법인카드 목록, 등록/수정, 월 한도, 사용 이력과 사용 상태를 관리합니다.
  - FinanceHom의 자금 관리 안에서 법인카드 탭으로 재사용합니다.

Approval.js
  - 지출 결재 목록, 기안서 작성, 승인/반려, 결재 단계와 증빙파일을 관리합니다.
  - 지급 현황·지급 등록은 ApprovalPayments를 연결하여 사용합니다.
  - 통합 화면에서는 전달받은 설정에 따라 작성 버튼 등이 제한됩니다.


3. components 폴더: 여러 화면에서 재사용하는 UI

[신규] FinanceSearchForm.js
  - 공통 검색 폼: 필터, 검색어 입력, 조회 버튼.
  - 사용: BankAccount, CorpCard, Approval.
  - 화면에서 filters, keyword, onSubmit을 전달합니다.
  - 검색 조건 적용·데이터 필터링 자체는 각 화면에서 처리합니다.

[신규] FinancePaymentHistory.js
  - 공통 입출금 이력 표.
  - 사용: BankAccount, CorpCard, Items.
  - payments로 목록을 전달합니다.
  - showPartner, amountSuffix, statusLabel로 화면별 표시를 조정합니다.
  - 로딩·오류·빈 목록 안내는 호출 화면에서 처리합니다.

[신규] FinanceDetailRows.js
  - 상세정보의 항목명/값 행을 공통으로 표시합니다.
  - 사용: Partners, CorpCard, Approval, Items.
  - 기존 table의 tbody 안에 넣고 rows={[[항목명, 값], ...]}를 전달합니다.
  - table이나 tbody를 새로 만드는 컴포넌트가 아닙니다.

[신규] FinanceStatusBadge.js
  - 상태 문구를 공통 배지 형태로 표시합니다.
  - 사용: BankAccount, CorpCard, Approval.
  - tone으로 기존 상태 색상 클래스를, children으로 문구를 전달합니다.
  - 승인 여부나 계좌 상태를 판정하는 기능은 각 화면에 유지합니다.

ApprovalPayments.js
  - 승인된 결재 문서의 지급 현황·내역과 지급 등록 폼입니다.
  - Approval에서 재사용하며 계좌·카드 선택과 지급 입력을 처리합니다.

FinanceDocumentForm.js
  - 영수증·청구서·견적서 작성, 미리보기, 저장과 인쇄를 담당합니다.
  - FinanceModul에서 문서 종류에 따라 재사용합니다.


4. components 폴더: 공통 처리 함수와 훅

[신규] useFinanceHistory.js
  - 계좌·카드의 선택 이력을 조회하는 공통 React 훅입니다.
  - 사용: BankAccount, CorpCard.
  - 조회 함수·선택 ID·기본 오류 문구를 받고 payments/loading/error를 반환합니다.
  - 다른 항목을 선택하거나 화면을 떠난 뒤 이전 응답이 반영되지 않게 처리합니다.

[신규] financeUtils.js
  - getFinanceError: 서버 오류 문구가 있으면 사용하고, 없으면 화면별 기본 문구를 반환합니다.
  - koreaDate: 한국 시간 기준 YYYY-MM-DD 문자열을 만듭니다.
  - toFinanceCard: 서버의 법인카드 응답을 화면에서 사용하는 필드와 숫자로 변환합니다.
  - 여러 재무 화면에서 필요한 함수만 가져와 사용합니다.

approvedTradeRows.js
  - 결재 문서를 거래 목록용 행으로 변환합니다.
  - normalizeApprovalStatus로 승인 상태를 표시·필터용 값으로 정리합니다.
  - Items에서 사용합니다. 실제 DB 거래를 새로 만드는 함수는 아닙니다.

payrollPurchaseRows.js
  - 승인된 월별 급여 요약을 매입·인건비 목록용 행으로 변환합니다.
  - Items에서 사용합니다. 실제 지급 등록은 Items의 별도 처리에서 실행합니다.

financeDocumentUtils.js
  - 문서 종류, 날짜·통화 표시, 품목별 공급가/세액과 합계 계산을 제공합니다.
  - 문서 인쇄 및 문서 저장/조회·문서용 거래처 조회 API 요청도 포함합니다.
  - FinanceDocumentForm과 문서 조회 기능에서 사용합니다.


5. CSS 및 외부 공통 파일

components/Finance.css
  - 재무 화면 전용 스타일입니다.
  - 재무 UI의 크기, 간격, 색상과 배치를 조정할 때 우선 확인합니다.
  - 이번 UI 공통화 작업에서는 수정하지 않았습니다.

src/utils/financeService.js
  - 재무 폴더 밖에 있는 프론트엔드 API 호출 함수 모음입니다.
  - axios로 거래처·품목·계좌·카드·결재 등의 조회/등록/수정 요청을 보냅니다.
  - DB에 직접 접속하는 백엔드 서비스 파일과 구분합니다.
  - 문서 전용 API는 financeDocumentUtils에도 있으므로 문서 기능 수정 시 함께 확인합니다.

src/components 및 src/css
  - 다른 파트에서도 사용하는 팀 공용 파일입니다.
  - 기존 공용 컴포넌트를 우선 재사용하며, 내부 내용은 임의로 수정하지 않습니다.
  - ModalBase: 모달 / PaginationTable·BasicTable: 목록 표와 페이지네이션.
  - FilterControls: 탭·라디오·체크박스·선택창.
  - StatisticsCard: 통계 카드 / BasicCalendar·WeeklyCalendar: 달력.
  - 재무의 거래처·품목 주간/월간 전환은 기존 FilterTabs를 재사용합니다.
  - 재무만의 변경은 재무 내부 컴포넌트나 Finance.css에서 처리합니다.


6. 주요 화면 주소와 연결 위치

/main/finance
  - FinanceHom → FinanceModul: 재무 메인 화면.
/main/finance/partners
  - FinanceHom → Partners: 거래처 관리.
/main/finance/items
  - FinanceHom → FinanceWorkspace → PaymentManagement: 지출·거래 관리.
/main/finance/items?view=legacy
  - FinanceWorkspace → Approval: 기존 결재·이력.
/main/finance/funds?tab=cards
  - FinanceHom의 FinanceFunds → CorpCard: 법인카드 탭.
/main/finance/funds?tab=accounts
  - FinanceHom의 FinanceFunds → BankAccount: 회사계좌 탭.

기존 corp-card, bank-account, approval 주소의 리다이렉트는 FinanceHom에서 확인합니다.
프론트엔드 메뉴 노출과 화면 권한 확인은 서버의 API 권한 검증을 대체하지 않습니다.


7. 이름 규칙과 수정할 때 확인할 곳

- 대문자 시작: React UI 컴포넌트. 예: FinanceSearchForm.js.
- 소문자 시작: 데이터 변환·계산·API 등 일반 함수. 예: financeUtils.js.
- use 시작: React 커스텀 훅. 예: useFinanceHistory.js.
- 현재 components 폴더에는 UI뿐 아니라 일반 함수와 훅도 함께 보관합니다.
- 실제 파일명 FinanceHom.js, FinanceModul.js는 기존 import에 맞춰 유지합니다.

메뉴·주소·자금 탭 연결 수정: FinanceHom.js
재무 메인 화면 수정: FinanceModul.js
업무별 등록·수정·지급 동작 수정: 해당 pages 파일
반복 UI 수정: FinanceSearchForm / FinancePaymentHistory / FinanceDetailRows / FinanceStatusBadge
공통 이력 조회 수정: useFinanceHistory.js
공통 오류·한국 날짜·카드 변환 수정: financeUtils.js
재무 디자인 수정: components/Finance.css
일반 재무 API 요청 수정: src/utils/financeService.js
영수증·청구서·견적서 수정: FinanceDocumentForm.js / financeDocumentUtils.js

공통 파일을 수정하면 여러 재무 화면에 함께 반영됩니다.
변경 후에는 해당 파일을 사용하는 화면들을 같이 확인합니다.
신규 공통 파일에는 [신규 추가], 기존 파일의 공통화 import에는 [공통화 추가] 표시가 있습니다.


8. 이전 파일 정리 시 구분

- finance/mock/approvedDrafts.js는 받은 버전에서 비활성화되어 있고 참조가 없어 삭제 가능합니다.
- pages/approvedTradeRows.js, pages/payrollPurchaseRows.js도 받은 재무 코드에서 참조가 없는 이전 파일입니다.
- components/approvedTradeRows.js, components/payrollPurchaseRows.js는 실제 사용 중이므로 유지합니다.
- 위 이전 파일들이 아직 남아 있어도 이 안내의 현재 사용 파일 목록에는 포함하지 않았습니다.
- finance_ui_changes.patch는 변경 비교용 파일이며 앱에서 실행하거나 import하지 않습니다.

이 안내는 공유받은 프론트엔드와 공통화 적용본을 기준으로 작성했습니다.
추후 파일명·경로·사용처를 바꾸면 이 안내도 함께 갱신합니다.
